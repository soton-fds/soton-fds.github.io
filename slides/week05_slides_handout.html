Joins, Strings and Dates

Objectives

By the end of this lecture you will be able to:

  • explain why data is often split across several tables, and combine them with dplyr’s *_join() functions
  • clean and standardise free text with stringr
  • parse and work with dates, times and time zones using lubridate

Setup

Packages

library(tidyverse)   # includes stringr and lubridate
library(janitor)     # helpers for messy data

stringr (strings) and lubridate (dates) come with the tidyverse. janitor is a separate package — install it once in the console if you don’t have it.

ID in one table matches Student ID in the other. Each student has many grades: a one-to-many relationship.

Why not one big table?

  • Size: a flat table repeats every student’s name for every course
  • Integrity: a name change is made in one place
  • Flexibility: new tables (e.g. references) can link to students without touching grades
  • Clarity: the structure mirrors the real world — “each student takes many courses”

Keep this short — the point is that real data arrives split up on purpose, so joining is a routine step, not a workaround. The SQL week will return to this idea.

Where did the rows go?

ImportantTask

[1] 59

[1] 21 22

An inner join keeps only rows with a match in both tables.

Students 21 and 22 have grades but no student record; student 7 has no grades at all. anti_join(student_data, student_grades, by = ...) answers the same question and returns the full rows — it’s in the notes.

left_join, right_join, full_join

Join Keeps
inner_join rows matched in both tables
left_join every row of the left table
right_join every row of the right table

Two common surprises

WarningDuplicated column names

If both tables have a non-key column with the same name (say notes), you get notes.x and notes.y. Control this with the suffix argument.

WarningMany-to-many joins

If both tables have several rows per key, you get every combination — the row count can explode. dplyr warns you; it is usually a mistake.

Rule of thumb: check nrow() before and after every join.

Strings

stringr

Every function starts str_ and is vectorised: it works on one string or a whole column.

str_length(c("Alice", "Bob", "Dave"))
[1] 5 3 4

Free text from forms is rarely clean:

messy_names <- c("  Alice  ", "BOB", "cara-mae", "  dave ")

Case and whitespace

ImportantTask

Remove the stray spaces from messy_names and give them consistent capitalisation.

str_trim(messy_names)
[1] "Alice"    "BOB"      "cara-mae" "dave"    
str_squish("  too    many   spaces ")
[1] "too many spaces"
str_to_title(str_squish(messy_names))
[1] "Alice"    "Bob"      "Cara-Mae" "Dave"

str_trim() removes spaces at the ends; str_squish() also collapses runs inside. Case: str_to_lower(), str_to_upper(), str_to_title().

Detecting patterns

ImportantTask

Which names contain an "a"? Why isn’t "Alice" one of them?

str_detect(messy_names, "a")
[1] FALSE FALSE  TRUE  TRUE
str_detect(str_to_lower(messy_names), "a")
[1]  TRUE FALSE  TRUE  TRUE

Matching is case-sensitive — standardise case first. str_detect() returns TRUE/FALSE, so it drops straight into filter().

Replacing and removing

ImportantTask

Turn "cara-mae" into "cara mae", and get just the number from "MATH6195".

str_replace("cara-mae", "-", " ")
[1] "cara mae"
str_replace_all("a-b-c-d", "-", "_")
[1] "a_b_c_d"
str_remove("MATH6195", "MATH")
[1] "6195"

str_replace() changes the first match; str_replace_all() changes every match.

Dates

Dates are ambiguous

Is 08/11/2025 11 August or 8 November?

ImportantTask

Parse "2025-August-11", "11/08/25" and "8.11.2025" as the same date.

d1 <- ymd("2025-August-11")
d2 <- dmy("11/08/25")
d3 <- mdy("8.11.2025")
c(d1, d2, d3)
[1] "2025-08-11" "2025-08-11" "2025-08-11"
class(d1)
[1] "Date"

You tell lubridate the order (ymd, dmy, mdy); it copes with the separators. Always check parsed dates.

For full control, as.Date(x, format = "%d/%m/%Y"). The printed date looks like a string but has class Date, so arithmetic works.

Why not today() - date_of_birth? That gives days — and converting days to years is awkward because of leap years.

Why sort by date_of_birth rather than desc(age)? Rounded ages tie — lots of students are 24 — and ties keep their original (ID) order. Dates sort chronologically, so they give the true order. Also month(), day(). as.period() gives an exact “years, months, days” difference — in the notes.

Times and time zones

ImportantTask

A server logs an event at 2025-08-11 11:33:01 UTC. What did the clocks in Tokyo say at that moment?

t1 <- ymd_hms("2025-08-11 11:33:01")
tz(t1)
[1] "UTC"
with_tz(t1, "Asia/Tokyo")    # convert: read the same moment off a Tokyo clock
[1] "2025-08-11 20:33:01 JST"

Same event, so only the displayed time changes: 11:33 UTC is 20:33 in Tokyo.

Fixing the wrong time zone

ImportantTask

A sensor in Tokyo wrote 2025-08-11 11:33:01 in Tokyo local time, but R read it as UTC. Correct the time zone.

t2 <- force_tz(t1, "Asia/Tokyo")   # relabel: keep 11:33, change the zone
t2
[1] "2025-08-11 11:33:01 JST"
t2 - t1                            # a genuinely different moment
Time difference of -9 hours

Time Zone Summary

Clock shows Is it the same event?
with_tz() changes (11:33 → 20:33) yes — just viewed from Tokyo
force_tz() stays 11:33 no — now 9 hours earlier

Use with_tz() to view a correct time somewhere else. Use force_tz() only to fix a time that was recorded with the wrong zone.
