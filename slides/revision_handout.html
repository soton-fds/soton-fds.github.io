Data Wrangling and Joins

What should one row represent?

shop_data <- tibble(
  shop = c("North", "South"),
  revenue_2023 = c(120, 90), cost_2023 = c(100, 95),
  revenue_2024 = c(150, 130), cost_2024 = c(110, 105)
)
shop_data
# A tibble: 2 × 5
  shop  revenue_2023 cost_2023 revenue_2024 cost_2024
  <chr>        <dbl>     <dbl>        <dbl>     <dbl>
1 North          120       100          150       110
2 South           90        95          130       105

We want four rows, one per shop per year, with columns shop, year, revenue and cost.

The assessment will state the required final shape, including what each row should represent and which measurements should be in separate columns.

There are two shops and two years, so we want four rows. At the moment, the year is part of the column name. We want it in its own column, with revenue and cost side by side for each shop and year.

Making the data longer

Collect the measurement columns into measure_year and amount.

shop_long <- shop_data |>
  pivot_longer(
    cols = -shop,
    names_to = "measure_year",
    values_to = "amount"
  )
shop_long |> head(1)
# A tibble: 1 × 3
  shop  measure_year amount
  <chr> <chr>         <dbl>
1 North revenue_2023    120

There are now eight rows: one per shop, measurement and year.

Show where revenue_2023 ends up in measure_year. The shop name repeats for each measurement, and the numbers go into amount.

Splitting names and widening

Split the measurement from the year, then put revenue and cost in separate columns.

shop_tidy <- shop_long |>
  separate_wider_delim(
    measure_year, delim = "_", names = c("measure", "year")
  ) |>
  pivot_wider(names_from = measure, values_from = amount) |>
  mutate(year = as.integer(year))
shop_tidy
# A tibble: 4 × 4
  shop   year revenue  cost
  <chr> <int>   <dbl> <dbl>
1 North  2023     120   100
2 North  2024     150   110
3 South  2023      90    95
4 South  2024     130   105

Follow revenue_2023 through the steps: split it into revenue and 2023, then use revenue to name a column. Convert the year from text to a number.

Splitting names with names_sep

Split the names as we pivot.

shop_split <- shop_data |>
  pivot_longer(
    cols = -shop,
    names_to = c("measure", "year"),
    names_sep = "_",
    values_to = "amount"
  )
shop_split |> head(1)
# A tibble: 1 × 4
  shop  measure year  amount
  <chr> <chr>   <chr>  <dbl>
1 North revenue 2023     120

revenue_2023 splits into measure = "revenue" and year = "2023".

The result still has eight rows. Here, the underscore separates parts of a column name. It has nothing to do with the separator in the CSV file.

Results by club

# A tibble: 5 × 3
  person_id club  score
      <dbl> <chr> <dbl>
1         1 N        12
2         2 N        15
3         3 S        10
4         4 S        17

Each result has a club code. We will join on the club names from a lookup table.

Several results share the same club code. The club lookup should have one row per code.

Joining on columns with different names

Match club in the results to code in the lookup.

joined <- results |>
  left_join(clubs, by = c("club" = "code"))
joined |> select(club, club_name)
# A tibble: 5 × 2
  club  club_name 
  <chr> <chr>     
1 N     North Club
2 N     North Club
3 S     South Club
4 S     South Club
5 X     <NA>

left_join() keeps results with no matching club name too.

In by, club is the name in results and code is the name in clubs. An inner join would lose the row with club X. The left join keeps it, with a missing club name.

Checking a join

Check for repeated lookup keys and result rows with no match.

clubs |> count(code) |> filter(n > 1)
# A tibble: 0 × 2
# ℹ 2 variables: code <chr>, n <int>
results |> anti_join(clubs, by = c("club" = "code"))
# A tibble: 1 × 3
  person_id club  score
      <dbl> <chr> <dbl>
1         5 X        14
  • More than one match for a key can duplicate rows.
  • An inner join drops rows whose keys have no match.
  • Check the keys as well as the row count.

The lookup is missing club X. Find out why before changing the code or discarding the row. For MATH6195, checking for lost data matters too. A join can lose some rows and duplicate others, leaving the total unchanged.

Many-to-many joins

Two rows in x have key "A". Three rows in y have key "A".

The join produces six rows for "A": each row in x matches all three rows in y.

This might mean the key is missing a column, or that there are duplicate records. Sometimes all six matches are what we want.

A two-by-three sketch may help here. Setting relationship = “many-to-many” tells dplyr that the matches are intentional. It does not change which rows match.

Debugging quickly

Finding the problem

  1. Start with the first error message.
  2. Run the code a line or a chunk at a time to find where it fails.
  3. Check the object just before that line: column names, types and values.
  4. Change one thing, then try again.
  5. Render the whole document again.

Also check the output. R cannot tell you whether you have answered the question.

Useful functions here are names(), glimpse(), head(), count() and is.na(). Use these to inspect the object at the point where the code fails.
