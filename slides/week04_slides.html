Data Wrangling in R

Objectives

By the end of this lecture you will be able to:

  • load delimited data into R with readr (read_csv(), read_delim())
  • transform data with the core dplyr verbs — mutate(), select(), filter(), arrange(), summarise()
  • aggregate within groups using group_by() and count()
  • reshape between long and wide with tidyr’s pivot_*() functions

Setup

One Import is All You Need

library(tidyverse)   # readr + dplyr + tidyr + ggplot2 + ...

The tidyverse is a bundle of packages that share a design philosophy. Loading it gives us readr (loading), dplyr (transforming) and tidyr (reshaping) all at once.

Point out the startup message: it lists the attached packages and flags any conflicts (e.g. dplyr::filter() masks stats::filter()). This is normal. Contrast with library(dplyr) alone from last week — today we want the whole toolkit.

dplyr: transforming data

The five verbs

dplyr gives us a small set of readable verbs:

  • mutate() — add or change columns
  • select() — pick columns
  • filter() — pick rows
  • arrange() — reorder rows
  • summarise() — collapse many rows to a summary

We’ll demo them on gapminder: country-level life expectancy, population and GDP per capita over time.

Tidyverse functions don’t modify their input

Task

Check: does gapminder now have a gdp_billions column?

gapminder$gdp_billions
NULL

NULL (or an error) — mutate() returned a copy; it never touched the original. To keep the change we must assign it back.

gapminder <- gapminder |>
  mutate(gdp_billions = gdpPercap * pop / 1e9)

Tidyverse verbs are pure functions — input in, new tibble out, original untouched. More in the functional programming chapter.

summarise: many rows → one

Task

What is the mean gdp_billions across all Asian rows?

gapminder |>
  filter(continent == "Asia") |>
  summarise(mean_gdp = mean(gdp_billions))
# A tibble: 1 × 1
  mean_gdp
     <dbl>
1     227.

summarise() collapses a whole tibble to a single row. It works with mean, median, sum, min, max, and counts via n() / n_distinct().

This feels underwhelming on its own — one number. The payoff is the next slide: summarise() becomes powerful once we tell it to work per group.

Grouping

group_by + summarise

Task

Compute the mean life expectancy for each continent.

gapminder |>
  group_by(continent) |>
  summarise(avg_lifeExp = mean(lifeExp))
# A tibble: 5 × 2
  continent avg_lifeExp
  <fct>           <dbl>
1 Africa           48.9
2 Americas         64.7
3 Asia             60.1
4 Europe           71.9
5 Oceania          74.3

group_by() doesn’t change the data — it tags it. The next summarise() then runs once per group, giving one row per continent.

Do gapminder |> group_by(continent) on its own first: the printout gains a Groups: continent [5] line but the rows look identical. Then add the summarise and watch it collapse. That “tag, then aggregate” model is the thing to land.

A real question

Task

Which countries have the highest average GDP since 1960?

We first need to parse this into a sequence of verbs:

  • Group by country,
  • Filter to years after 1960,
  • Summarize to get the average GDP (bonus: max, and number of records).
gapminder |>
  filter(year > 1960) |>
  group_by(country) |>
  summarise(
    mean_gdp = mean(gdp_billions),
    max_gdp  = max(gdp_billions),
    n_years  = n(),
    .groups  = "drop"
  ) |>
  arrange(desc(mean_gdp))

This is the centrepiece — build it line by line, re-running after each pipe so they see the tibble grow columns. Points to make live:

  • n() counts rows in each group.
  • .groups = "drop" silences the “grouped output” message (optional, but tidy).
  • If mean/max ever return NA, add na.rm = TRUE — demo by introducing an NA if you have time.

Order matters: filter early

Both of these give the same answer. Which is cheaper?

# A: compute for every row, then throw most away
gapminder |>
  mutate(gdp_billions = gdpPercap * pop / 1e9) |>
  filter(year == 2007, continent == "Asia")

# B: throw rows away first, then compute
gapminder |>
  filter(year == 2007, continent == "Asia") |>
  mutate(gdp_billions = gdpPercap * pop / 1e9)

B is cheaper. Filtering first means mutate() runs on ~30 rows, not ~1700. Rule of thumb: filter() as early as you can.

On gapminder the difference is invisible, but on a million-row dataset it’s the difference between instant and painful. This is the one performance idea to give them today.

tidyr: reshaping data

Long vs. wide

The inverse: pivot_longer

Task

Turn the wide table back into a tall one.

gapminder_wide |>
  pivot_longer(
    cols = -country,
    names_to = "year",
    values_to = "lifeExp"
  )
# A tibble: 1,704 × 3
   country     year  lifeExp
   <fct>       <chr>   <dbl>
 1 Afghanistan 1952     28.8

 8 Afghanistan 1987     40.8

cols = -country means “every column except country” — a tidyselect helper, so we don’t list all the years by hand.

pivot_longer and pivot_wider are inverses. Note year comes back as <chr> text, not a number — it was a column name a moment ago. A quick mutate(year = as.integer(year)) fixes it if asked. Also mention separate_wider_delim() from the notes for splitting one column into two (the table3 “cases/population” case) if time allows.

Wrap-up

Today you can now:

  • load delimited data with read_csv() / read_delim()
  • transform with mutate, select, filter, arrange, summarise
  • aggregate per group with group_by() and count()
  • reshape with pivot_wider() and pivot_longer()
