Setup

Packages

install.packages("dplyr")   # ONCE, in the console
library(dplyr)              # EVERY new session

Never put install.packages() in a .qmd

Quarto re-runs every chunk on every render — the package would be re-installed from CRAN each time you render.

Rule: Install in the console; load with library() in the document.

Variables & types

Your first variables

Task

Create three variables — a number, some text, and a truth value — then ask R what type each one is.

x <- 5
y <- "Hello"
z <- TRUE

typeof(x)
[1] "double"
typeof(y)
[1] "character"
typeof(z)
[1] "logical"

Point out double, character, logical. Mention the chapter’s aside: <- is idiomatic R, = is fine, both accepted in assessments.

R is dynamically typed

Task

Demonstrate dynamic typing in R

number <- 5
typeof(number)
[1] "double"
number <- "hello"
typeof(number)
[1] "character"

R does not require variable types. It also does not check types when you call a function!

Vectors

Building vectors

Task

Make a vector of the numbers 1 to 5 with c(), then check its type and length. What happens if you check the length of the plain number x from before?

vector <- c(1, 2, 3, 4, 5)

typeof(vector)   # still "double"!
[1] "double"
length(vector)
[1] 5
length(x)        # scalars ARE length-1 vectors
[1] 1

In R there are no scalars — everything is a vector.

Indexing: R counts from 1

Task

Get the 2nd element, the 5th element, and elements 2 through 4.

vector[2]
[1] 2
vector[5]     # the LAST element — it would be index 4 in Python!
[1] 5
vector[2:4]
[1] 2 3 4

Show vector[0]: it returns an empty vector, no error.

Logical indexing

Task

Use a vector of TRUE/FALSE to pick out elements — then negate it with ! to pick the others.

elements <- c(TRUE, FALSE, TRUE, TRUE, FALSE)

vector[elements]    # positions 1, 3, 4
[1] 1 3 4
vector[!elements]   # elementwise negation: positions 2, 5
[1] 2 5

This is the idiom that powers filtering data in every week to come.

Lists & data frames

Lists: containers for anything

Task

Build a list about a penguin — two bits of text, a numeric vector, and a count — then pull out elements by name and by position.

l <- list(
  name = "Flipper",
  species = "Adelie",
  measurements = c(210, 217, 230),
  n_measurements = 3
)

l$name
[1] "Flipper"
l$measurements
[1] 210 217 230
l[[3]]
[1] 210 217 230

Demo the difference between [3] and [[3]] - a list vs. the element. Comment on why the names might be better than the numbers.

Vectorised conditionals

Reminder: if / else

x <- 1
if (x < 0) {
  print("x was negative")
} else if (x == 0) {   # else MUST be on the same line as }
  print("x was 0")
} else {
  print("x was positive")
}

~1 min. They have seen if/else before — don’t dwell. Two things to say: else must be on the same line as the closing brace, and plain if makes ONE decision. The real question: what if we need the same decision for every element of a vector? → next slide.

if_else: a vectorised conditional

Task

Classify each element of x <- c(3, 1, 4, 1, 5) as “big” or “small” depending on whether it exceeds 2.

library(dplyr)
x <- c(3, 1, 4, 1, 5)

if_else(x > 2, "big", "small")
[1] "big"   "small" "big"   "small" "big"

case_when: many conditions

Task

Classify x as “small” (< 2), “medium” (< 5), or “large” (everything else).

case_when(
  x < 2 ~ "small",
  x < 5 ~ "medium",
  TRUE  ~ "large"
)
[1] "medium" "small"  "medium" "small"  "large"

Order matters: swap the first two conditions and “small” disappears.

Functions

Writing Functions

Task

Write a function add(x, y).

add <- function(x, y) {
  x + y        # the LAST expression is the return value
}

add(1, 10)
[1] 11

No return() needed.

Guard clauses: return

Task

Write clip(x, lower, upper) that forces a value into a range — e.g. for cleaning impossible measurements.

clip <- function(x, lower, upper) {
  if (x < lower) return(lower)   # guard clause
  if (x > upper) return(upper)
  x                              # still here? it's in range
}

clip(5, 0, 10)
[1] 5
clip(-3, 0, 10)
[1] 0
clip(42, 0, 10)
[1] 10

Note that you could also use case_when to do this

Functions are Variables

sapply(1:10, function(x) clip(x, 3, 7))
 [1] 3 3 3 4 5 6 7 7 7 7

A function you never named — an anonymous function — passed straight into sapply.

It is called a “higher order function.”

Pipes

Composing functions: f(g(x))

times_ten <- function(y) y * 10
add_five <- function(x) x + 5

x <- 10
times_ten(add_five(x))

Readable — up to a point.

The pipe: |>

Task

Implement the above logic using the pipe operator |>

x |> add_five() |> times_ten()
[1] 150

Much more readable.

The parentheses after each function are required — the pipe inserts the left-hand side into the FIRST argument.

Mention %>% (magrittr) exists and behaves almost identically, but |> is base R.

Wrap-up

When you’re stuck

  • ?mean — documentation (also ?dplyr, even ?`+`)
  • example(mean) — run the docs’ examples
  • ??"linear regression" — search all installed packages
  • Read the error message first — then search it verbatim online

AI tools

Great for getting unblocked — but they hallucinate. Verify everything with ?, and never paste sensitive data into them. The docs are always right; the AI is usually helpful.
