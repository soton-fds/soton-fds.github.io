Data Wrangling and Joins

Reading different file formats

Look inside the file: what separates the columns, and how are decimals written?

shop|area
North|12.5
shop;area
North;12,5
shop    area     (columns separated by a tab)
North   12.5

These are extracts from three example files. The last one uses tabs, which can be hard to distinguish from spaces on screen. The area should come out as 12.5 in all three cases.

Loading and checking the data

areas_1 <- read_delim("areas_pipe.txt", delim = "|")
areas_2 <- read_csv2("areas_semicolon.csv")
areas_3 <- read_tsv("areas_tab.txt")

head(areas_2)
glimpse(areas_2)
all(areas_1 == areas_2)
all(areas_1 == areas_3)

read_csv2() uses semicolons between fields and decimal commas. A file can load without errors and still be read incorrectly. Check the values and column types.

These filenames are examples. The equality checks assume the rows and columns are in the same order and there are no missing values. For other data, match the rows first and consider all.equal for decimal values. The file extension does not always tell you how the contents are arranged.

What should one row represent?

shop_data <- tibble(
  shop = c("North", "South"),
  revenue_2023 = c(120, 90), cost_2023 = c(100, 95),
  revenue_2024 = c(150, 130), cost_2024 = c(110, 105)
)
shop_data
# A tibble: 2 × 5
  shop  revenue_2023 cost_2023 revenue_2024 cost_2024
  <chr>        <dbl>     <dbl>        <dbl>     <dbl>
1 North          120       100          150       110
2 South           90        95          130       105

We want four rows, one per shop per year, with columns shop, year, revenue and cost.

The assessment will state the required final shape, including what each row should represent and which measurements should be in separate columns.

There are two shops and two years, so we want four rows. At the moment, the year is part of the column name. We want it in its own column, with revenue and cost side by side for each shop and year.

Making the data longer

shop_long <- shop_data |>
  pivot_longer(
    cols = -shop,
    names_to = "measure_year",
    values_to = "amount"

shop_long |> head(4)
# A tibble: 4 × 3

  <chr> <chr>         <dbl>
1 North revenue_2023    120
2 North cost_2023       100
3 North revenue_2024    150

There are now eight rows: one per shop, measurement and year.

Show where revenue_2023 ends up in measure_year. The shop name repeats for each measurement, and the numbers go into amount.

Splitting the names and making the data wider

shop_tidy <- shop_long |>
  separate_wider_delim(
    measure_year, delim = "_", names = c("measure", "year")
  ) |>
  pivot_wider(names_from = measure, values_from = amount) |>
  mutate(year = as.integer(year))
shop_tidy
# A tibble: 4 × 4
  shop   year revenue  cost
  <chr> <int>   <dbl> <dbl>
1 North  2023     120   100
2 North  2024     150   110
3 South  2023      90    95
4 South  2024     130   105

Follow revenue_2023 through the steps: split it into revenue and 2023, then use revenue to name a column. Convert the year from text to a number.

names_sep combines the first two steps

shop_split <- shop_data |>
  pivot_longer(
    cols = -shop,
    names_to = c("measure", "year"),
    names_sep = "_",
    values_to = "amount"

shop_split |> head(2)
# A tibble: 2 × 4
  shop  measure year  amount
  <chr> <chr>   <chr>  <dbl>
1 North revenue 2023     120
2 North cost    2023     100

revenue_2023 splits into measure = "revenue" and year = "2023". We still have one amount column.

The result still has eight rows. Here, the underscore separates parts of a column name. It has nothing to do with the separator in the CSV file.

Calculating profit

shop_profit <- shop_tidy |>
  mutate(profit = revenue - cost)
shop_profit |> select(shop, year, profit)
# A tibble: 4 × 3
  shop   year profit
  <chr> <int>  <dbl>
1 North  2023     20
2 North  2024     40
3 South  2023     -5
4 South  2024     25

North’s profit rises from 20 to 40. South moves from a loss of 5 to a profit of 25.

Both shops make more profit in the second year. North makes more in both years. We can describe the change, but these figures do not tell us why it happened.

What does a row represent here?

# A tibble: 5 × 4
  person_id club  event  award    
      <dbl> <chr> <chr>  <chr>    
1         1 N     Relay  Winner   
2         2 N     Relay  Winner   
3         1 N     Sprint Winner   
4         3 S     Sprint Runner-up
5         4 X     Jump   Winner

There are five rows, four different people, and three wins when we count each event once per winning club.

Person 1 appears twice because they entered two events. The relay also appears twice because two members of the winning team are listed. Counting rows would overcount both people and team wins.

Joining on columns with different names

clubs <- tibble(
  code = c("N", "S"),
  club_name = c("North Club", "South Club")
)
joined <- results |>
  left_join(clubs, by = c("club" = "code"))
joined |> select(person_id, club, club_name)
# A tibble: 5 × 3
  person_id club  club_name 
      <dbl> <chr> <chr>     
1         1 N     North Club
2         2 N     North Club
3         1 N     North Club
4         3 S     South Club
5         4 X     <NA>

Several rows in results can match the same row in clubs. left_join() keeps every result, including those with no matching club name.

In by, club is the name in results and code is the name in clubs. An inner join would lose the row with club X. The left join keeps it, with a missing club name.

Checking a join

clubs |> count(code) |> filter(n > 1)
# A tibble: 0 × 2
# ℹ 2 variables: code <chr>, n <int>
results |> anti_join(clubs, by = c("club" = "code"))
# A tibble: 1 × 4
  person_id club  event award 
      <dbl> <chr> <chr> <chr> 
1         4 X     Jump  Winner
  • More than one match for a key can duplicate rows.
  • An inner join drops rows whose keys have no match.
  • Check the keys as well as the row count.

The lookup is missing club X. Find out why before changing the code or discarding the row. For MATH6195, checking for lost data matters too. A join can lose some rows and duplicate others, leaving the total unchanged.

Counting people and counting events

results |>
  summarise(rows = n(), people = n_distinct(person_id))
# A tibble: 1 × 2
   rows people
  <int>  <int>
1     5      4
results |>
  filter(award == "Winner") |>
  group_by(club) |>
  summarise(wins = n_distinct(event), .groups = "drop") |>
  arrange(desc(wins))
# A tibble: 2 × 2
  club   wins
  <chr> <int>
1 N         2
2 X         1

North has two wins: the relay and the sprint. Club X has one. To add club names to this summary, join it to clubs and check the unmatched codes. Use n() for rows and n_distinct() for different people or events.

Many-to-many joins

Two rows in x have key "A". Three rows in y have key "A".

The join produces six rows for "A": each row in x matches all three rows in y.

This might mean the key is missing a column, or that there are duplicate records. Sometimes all six matches are what we want.

A two-by-three sketch may help here. Setting relationship = “many-to-many” tells dplyr that the matches are intentional. It does not change which rows match.

Debugging quickly

Finding the problem

  1. Start with the first error message.
  2. Run the code a line or a chunk at a time to find where it fails.
  3. Check the object just before that line: column names, types and values.
  4. Change one thing, then try again.
  5. Render the whole document again.

Also check the output. R cannot tell you whether you have answered the question.

Useful functions here are names(), glimpse(), head(), count() and is.na(). In each example, show what went wrong and how to check the fix.

Checking the units

distance_m is in metres. minutes is in minutes.

trips |> mutate(speed_kmh = distance_m / minutes)

Convert metres to kilometres and minutes to hours before dividing.

trips |>
  mutate(speed_kmh = (distance_m / 1000) / (minutes / 60))
# A tibble: 3 × 3
  distance_m minutes speed_kmh
       <dbl>   <dbl>     <dbl>
1       5000      30        10
2       3000      20         9
3         NA      25        NA

The first calculation gives metres per minute. After converting the units, the speeds are 10, 9 and NA. A missing distance gives a missing speed. Count missing values with sum(is.na(speed_kmh)). If you leave missing values out of a summary, say so.

When one pattern matches too much

case_when(
  str_detect(label, "paid") ~ "Paid",
  str_detect(label, "unpaid") ~ "Unpaid"
)

"unpaid assistant" matches "paid" too. Check the more specific pattern first.

label <- c("paid assistant", "unpaid assistant", "volunteer")
case_when(
  str_detect(label, "unpaid") ~ "Unpaid",
  str_detect(label, "paid") ~ "Paid",
  .default = "Other"
)
[1] "Paid"   "Unpaid" "Other"

The word unpaid contains paid. case_when uses the first condition that matches, so the order matters. Matching is case-sensitive by default. In a data frame, put this inside mutate() and check with count(category).

Making a crowded plot readable

ggplot(observations, aes(x = height, y = mass, colour = group)) +
  geom_point()

Make the points partly transparent so overlaps show up. Use shape as well as colour to distinguish the groups.

ggplot(observations, aes(height, mass, colour = group, shape = group)) +
  geom_point(alpha = 0.3, size = 1.5) +
  scale_colour_brewer(palette = "Dark2") +
  labs(x = "Height (cm)", y = "Mass (kg)",
       title = "Height and mass by group")

Here, observations is an example dataset with a categorical group column. Lower alpha makes dense parts of the plot darker. Shape gives readers another way to tell the groups apart. Check whether each point is a different person or a repeated observation, and explain any rows removed because of missing values.
