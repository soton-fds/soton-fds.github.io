6  Data Visualisation Principles

Objectives

  • Understand the grammar of graphics framework.
  • Be able to critique visualisations for clarity and effectiveness.
  • Know how visual perception affects the interpretation of plots.

6.1 The Grammar of Graphics Framework

The Grammar of Graphics (Wilkinson 2005) is implemented in R through the library ggplot2, a core library in tidyverse. It provides a systematic approach to constructing data visualisations. Rather than thinking about chart types (bar chart, scatter plot, etc.), the grammar breaks down visualisations into fundamental components that can be combined in flexible ways.

6.1.1 Core Components of the Grammar

The grammar consists of several key layers:

Data: The dataset being visualised. In ggplot2 this is assumed to be in tidy format. Aesthetics: referred to as aes in ggplot2. These are the visual properties that represent data variables, including:

  • Position (\((x,y)\) coordinates)
  • Colour (hue, saturation)
  • Shape (point shapes, line types)
  • Size (point size, line width)
  • Transparency (alpha values)

Geometries: the geometric objects that represent data points. How these are referred to in ggplot2 is included in parentheses below.

  • Points (geom_point())
  • Lines (geom_line())
  • Bars (geom_bar(), geom_col())
  • Areas (geom_area())
  • Text (geom_text())

Statistics (stat): (optional) statistical transformations applied to data before plotting, e.g.:

  • Count (frequency tables)
  • Smoothing (trend lines)
  • Binning (histograms)

Scales: How aesthetics translate data values to visual properties:

  • Continuous scales (for numeric data)
  • Discrete scales (for categorical data)
  • Colour scales (viridis colour maps, brewer colour palettes)
  • Position scales (log or square-root transformations)

Coordinate Systems: How data coordinates map to the plane of the plot:

  • Cartesian coordinates (most common)
  • Polar coordinates
  • Map projections

Faceting: Break data into subsets for producing multiple smaller charts:

  • facet_wrap(): arranges panels in rows and columns
  • facet_grid(): arranging panels in a grid based on variables.

6.1.2 Constructing Plots by Composing Components

The grammar allows components to be composed with one another by “adding” them to a plot to build visualisations incrementally.

6.1.2.1 Building a Plot Step by Step

Every ggplot2 plot begins with a call to ggplot(), to which we supply the data and an aesthetic mapping (aes) saying which variables should control which visual properties. On its own this sets up the axes but draws nothing, because we have not yet said how the data should be represented:

library(tidyverse)
penguins <- read_csv("data/penguins.csv")

ggplot(penguins, aes(x = flipper_length_mm, y = body_mass_g))

To actually see the data we add a geometry. Layers are combined with the + operator, and adding geom_point() draws one point per observation:

ggplot(penguins, aes(x = flipper_length_mm, y = body_mass_g)) +
  geom_point()

ggplot(penguins, aes(x = flipper_length_mm, y = body_mass_g, colour = species)) +

  geom_point() +
  labs(
    title = "Penguin flipper length vs body mass",

  theme_minimal()

Each step simply adds another component to the previous plot. (Thinking of it in this way may help you to distinguish from piping in the rest of tidyverse).

6.1.2.2 A Gallery of Examples

The examples below build on this same pattern to produce richer plots, each highlighting a different part of the grammar we listed above; we will go into building them in much more detail in the lab.

Building on the scatter plot above, we can split the data into a separate panel for each island using facet_wrap(~island), a convenient way to compare the same relationship across groups:

ggplot(penguins, aes(x = flipper_length_mm, y = body_mass_g, colour = species)) +
  geom_point() +
  facet_wrap(~island) +
  labs(
    title = "Penguin measurements by species, faceted by island",
    x = "Flipper length (mm)",
    y = "Body Mass (g)"
  ) +
  theme_minimal()

Because geometries are simply layers, we can stack several of them on a single plot. Here we add two geom_smooth trend lines on top of the scatter points: one per species (coloured) and one overall (dashed black). This lets us compare the per-species trends against the overall one. The points use alpha = 0.6 so that overlapping points show through, which is a common way to deal with overplotting:

ggplot(penguins, aes(x = flipper_length_mm, y = body_mass_g)) +
  geom_point(aes(colour = species), alpha = 0.6, size = 2) + # scatter points
  geom_smooth(aes(colour = species), method = "lm", se = TRUE) + # trend-line per species
  geom_smooth(method = "lm", colour = "black", linetype = "dashed", se = FALSE) + # overall trend line

Some geometries apply a statistical transformation to the data before anything is drawn. TipExtending ggplot2

Everything above uses ggplot2 itself, but one of its great strengths is that it can be extended by other packages that add new geometries, scales and facets. A few popular examples are ggforce (extra geometries such as sina plots and zoomed facets), patchwork (for combining several separate plots into one figure), and gganimate (for animated plots). These need to be installed separately (e.g. install.packages("ggforce")) and loaded with library() before use. A browsable catalogue is available at the ggplot2 extensions gallery.

6.2 Common Chart Types and When to Use Them

The grammar lets you build almost any plot, but in practice a handful of chart types cover most situations. A good starting point is to ask what kind of question you are trying to answer:

Question Typical chart Key geometry
How does a numeric value compare across categories? Bar chart geom_bar() / geom_col()
How is a single numeric variable distributed? Histogram, boxplot or violin geom_histogram(), geom_boxplot()
How are two numeric variables related? Scatter plot geom_point()
How does a value change over time (or another ordered variable)? Line chart geom_line()

We have already met scatter plots and histograms above; here are the other staples.

6.2.1 Bar Charts: geom_bar() vs geom_col()

There are two bar-chart geometries, and confusing them is a common source of frustration.

geom_bar() counts the rows in each category for you (it applies the count statistic). Use it when you want the frequency of raw observations, for example how many penguins there are of each species:

ggplot(penguins, aes(x = species)) +
  geom_bar() +
  labs(title = "Number of penguins per species", x = "Species", y = "Count") +
  theme_minimal()

geom_col(), by contrast, expects you to have already computed the height of each bar, and draws bars of exactly that height (it uses the identity statistic). Use it when your data already contains the values you want to plot, for example a mean you have calculated with dplyr:

penguins |>
  group_by(species) |>
  summarise(mean_mass = mean(body_mass_g, na.rm = TRUE)) |>
  ggplot(aes(x = species, y = mean_mass)) +
  geom_col() +
  labs(title = "Mean body mass per species", x = "Species", y = "Mean body mass (g)") +
  theme_minimal()

In short: reach for geom_bar() to count rows, and geom_col() when you already have the numbers.

6.2.2 Boxplots

A boxplot summarises a numeric variable across categories, showing the median, the interquartile range (the box) and the spread (the whiskers), along with any outliers:

ggplot(penguins, aes(x = species, y = body_mass_g)) +
  geom_boxplot() +
  labs(title = "Body mass by species", x = "Species", y = "Body mass (g)") +
  theme_minimal()
Warning: Removed 2 rows containing non-finite outside the scale range
(`stat_boxplot()`).

Boxplots are compact and good for comparing many groups, but they hide the underlying shape of the data (for example, whether it has two peaks). That is why overlaying the raw distribution, as in the violin and boxplot example above, can be useful.

6.2.3 Line Charts

A line chart connects observations in order along the \(x\)-axis, which makes it the natural choice for showing change over time. Here we use the gapminder dataset from Week 4 to plot life expectancy over time for three countries:

library(gapminder)
gapminder |>
  filter(country %in% c("United Kingdom", "China", "Rwanda")) |>
  ggplot(aes(x = year, y = lifeExp, colour = country)) +
  geom_line(linewidth = 1) +
  scale_colour_viridis_d(name = "Country") +
  labs(title = "Life expectancy over time", x = "Year", y = "Life expectancy (years)") +
  theme_minimal()

Because the line joins successive years, trends and turning points are easy to spot, such as the sharp drop in Rwanda in the early 1990s.

6.3 Visual Perception and Plot Interpretation

So far we have concentrated on how to build a plot. But being able to draw a figure is not the same as drawing a good one. ggplot gives us a lot of freedom to design our figures, and it does not tell us which designs are clear and which are misleading. For example, this plot gives the impression that welfare recipients in the US are spiralling out of control - but the \(y\)-axis starts from 94,000,000:

The next example was presented by General H.R. McMaster to US officials in 2009, intended to explain the complexity of US military strategy in Afghanistan. It led the New York Times to publish an article called We Have Met the Enemy, and He Is Powerpoint.

Careful thought is needed to ensure that plots effectively convey the information that we want them to convey.

6.3.1 Perceptual Accuracy of Visual Elements

(Cleveland and McGill 1984) developed a theory of graphical perception, the process by which people decode quantitative information from visual representations. They argue that the effectiveness of a graph depends on how accurately viewers can visually judge the data or information that the graph encodes. They rank elementary perceptual tasks, like judging position along a common scale, length, area, angle, colour etc. by how precisely humans can perform them, based on controlled experiments.

They found that:

  • Position along a common scale is judged most accurately,
  • Length, angle and slope are less accurate, with angle and slope worse than length,
  • Area, volume or colour saturation are even less reliable.

These provide guidance for how we should encode data into graphs. For example, bar charts (measuring length), aligned on a common scale (height) might be preferred to pie charts (comparing angle and area).

Since (Cleveland and McGill 1984), visualisation theory has continued to develop. The full theory is well beyond the scope of this course, but the main points are:

  • Not all visual encodings are equal. As (Cleveland and McGill 1984) shows, position can be read most accurately, then length/angle, then area/colour.
  • Design with perception in mind. Prioritise encodings that make the main comparison easier, using the most informative visual encoding.
  • Modern tools help. ggplot2 is based on the (Wilkinson 2005), which builds on these ideas. The mapping of aes to geoms describe these perceptual choices.

6.3.2 Colour Blindness Considerations

Another important concern is accessibility. Around 8% of men and 0.5% of women are affected by colour blindness, which can make some plots impossible to perceive for some users. It is also worthwhile to be mindful that your plots may be printed out in black-and-white or viewed on greyscale screens, so relying solely on colour to make points is better avoided.

The most common type of colour blindness is red-green deficiencies, so using red-green contrast should be avoided. Fortunately, ggplot makes it straightforward to adhere to this by providing perceptually uniform, colourblind-safe palettes such as viridis or the ColorBrewer safe sets. Where possible it is still best to make sure there is visual redundancy, rather than using colour alone, using label, shape or line type.

ggplot(penguins, aes(x = flipper_length_mm, y = body_mass_g, colour = species)) +
  geom_point(size=3) +
  scale_colour_manual(values=c("Adelie" = "red", "Chinstrap" = "green", "Gentoo" = "blue")) +
  theme_minimal()
Warning: Removed 2 rows containing missing values or values outside the scale range
(`geom_point()`).

It would be difficult for someone with red-green colour blindness to distinguish Adelie and Chinstrap penguins.

ggplot(penguins, aes(x = flipper_length_mm, y = body_mass_g, colour = species, shape=species)) +
  geom_point(size=3) +
  scale_colour_brewer(type="qual") +
  theme_minimal()
Warning: Removed 2 rows containing missing values or values outside the scale range
(`geom_point()`).

Using scale_colour_brewer with type="qual" tells R that this is qualitative data (as opposed to sequential, where the factor ordering is meaningful); an appropriate colour palette is then selected automatically. The addition of shape=species also ensures that a viewer who finds colour perception challenging will still be able to interpret the plot.

6.3.3 Principles for Honest and Effective Visualisation

ggplot2 will happily draw whatever you ask of it, so the responsibility for making a plot clear and honest rests with you. The following principles draw together the ideas above into a checklist you can use both to design a visualisation and to critique one:

  1. Be honest with scales. Choose axis limits that represent the data fairly. The welfare chart above is misleading precisely because its \(y\)-axis starts at 94,000,000, exaggerating a small relative change; for bar charts in particular, the value axis should usually start at zero.
  2. Choose the encoding that makes the key comparison accurate. Following (Cleveland and McGill 1984), prefer position and length over angle, area or colour for the comparison that matters most. This is why a bar chart is usually clearer than a pie chart.
  3. Reduce clutter. Every element should earn its place. The Afghanistan strategy diagram fails because it drowns the viewer in detail. When points overlap heavily (overplotting), transparency (the alpha setting used in several plots above) or jittering can reveal the underlying density.
  4. Label directly and informatively. Use labs() to give the plot a meaningful title and clearly labelled axes, with units where relevant, so the figure can be understood without external explanation.
  5. Design for accessibility. Use colourblind-safe palettes such as viridis, and add redundant encodings (shape, line type or direct labels) so the plot does not rely on colour alone.

It is worth running through this list whenever you make a plot, asking of each choice whether it helps or hinders the reader.
