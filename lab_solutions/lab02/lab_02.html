Part 1b: Lists

Recall that a list can hold a mixture of types, and that lists turn up all over R — in particular, they are how a function returns several results at once, and how we store a collection of records.

# The `na.rm = TRUE` arguments handle the second part of the task: with them,
# missing values are ignored by mean/min/max.
summarise_vector <- function(x) {
    list(
        mean = mean(x, na.rm = TRUE),
        min = min(x, na.rm = TRUE),
        max = max(x, na.rm = TRUE),

get_penguin_names <- function(penguins) {

For the primes, we write a helper that tests a single number, then use sapply to build a logical vector we can index with. A number is prime if it is at least 2 and has no divisors other than 1 and itself.

is_prime <- function(n) {
    if (n < 2) return(FALSE)
    if (n == 2) return(TRUE)
    # TRUE if none of 2..(n-1) divide n exactly
    !any(n %% 2:(n - 1) == 0)
}

Part (a): Conditionals

In data science we very often want to make the same decision for every element of a vector or column. Writing a for loop with an if inside would work, but the vectorised conditionals if_else and case_when are cleaner and faster. Both come from dplyr, so load it first:

library(dplyr)
Warning: package 'dplyr' was built under R version 4.4.3

We will apply them to the following data frame of students and their exam scores:

students <- data.frame(
    name = c("Ada", "Alan", "Grace", "Edsger", "Katherine"),
    score = c(72, 65, 43, 38, 91)
)
students$result <- if_else(students$score >= 40, "pass", "fail")

# Conditions are checked top to bottom, so the highest thresholds come first.
# TRUE acts as the catch-all "else" branch.
students$grade <- case_when(
    students$score >= 70 ~ "first",
    students$score >= 60 ~ "2:1",
    students$score >= 50 ~ "2:2",
    students$score >= 40 ~ "third",
    TRUE ~ "fail"
)

The modulo operator %% gives the remainder of a division, so year %% 400 == 0 tests whether year is divisible by 400.

Notestopifnot

stopifnot() is a handy way to check your work. Given one or more conditions, it does nothing if they are all TRUE, but raises an error as soon as one is FALSE. So once your function is correct the chunk below will run silently; until then, the first failing check tells you which case is wrong.

# The order of the branches matches the rule: 400 first, then 100, then 4.
is_leap_year <- function(year) {
    if (year %% 400 == 0) {
        TRUE
    } else if (year %% 100 == 0) {
        FALSE
    } else if (year %% 4 == 0) {
        TRUE
    } else {
        FALSE
    }
}

# Self-check: runs without error now that is_leap_year is correct
stopifnot(
    is_leap_year(2000) == TRUE,   # divisible by 400
    is_leap_year(2024) == TRUE,   # divisible by 4, not by 100
    is_leap_year(1900) == FALSE,  # divisible by 100, not by 400
    is_leap_year(2100) == FALSE   # divisible by 100, not by 400
)

check_for_na <- function(v) {
    for (element in v) {
        if (is.na(element)) {
            cat("The vector contains NA values.\n")
            return(invisible())
        }
    }
    cat("No NA values found.\n")
}

Your random walk uses randomly generated numbers, so it will produce different output every time the document is rendered. To make results reproducible — the same every time — look up set.seed() and call it once at the start of the chunk. We will return to why this matters for reproducibility later in the course.

# sample(c(-1, 1), 1) picks one of -1 or +1 with equal probability.
# The while loop continues as long as the particle is strictly inside (-10, 10).
random_walk <- function() {
    x <- 0
    steps <- 0
    while (x > -10 && x < 10) {
        x <- x + sample(c(-1, 1), 1)
        steps <- steps + 1
    }
    list(end = x, steps = steps)
}

# set.seed makes the "random" numbers reproducible: the same every render.
set.seed(42)

Part 4: Pipes

The pipe operator |> passes the value on its left into the first argument of the function on its right. Chaining pipes lets a sequence of nested function calls be read left-to-right, in the order they actually happen, rather than inside-out.

x <- c(4, 9, 16, 25)
round(mean(sqrt(x)), 1)
[1] 3.5

Reading the nested call from the inside out, we take sqrt, then mean, then round. The pipe lets us write that in the same order. The 1 becomes the second argument of round, since the piped value fills the first.

x |> sqrt() |> mean() |> round(1)
[1] 3.5

Tasks

# A data frame with some missing values
df <- data.frame(a = c(1, 2, 3, NA, 5), b = c(10, NA, 30, 40, 50))

apply(df, 1, sum) returns NA for any row containing an NA, because sum() propagates missing values by default. Passing na.rm = TRUE (which apply forwards to sum) ignores them instead.

row_sums <- apply(df, 1, sum, na.rm = TRUE)
print(row_sums)
[1] 11  2 33 40 55

The problem is recycling: when x and y have different lengths, R silently repeats the shorter one to match the longer (here b becomes c(5, 6, 5, 6)), so x - y computes something meaningless without complaint. The fix is a guard clause that stops with a clear error when the lengths differ, rather than returning a wrong answer.

distance <- function(x, y) {
    if (length(x) != length(y)) {
        stop("x and y must be the same length")
    }
    norm(x - y, type = "2")
}

a <- c(1, 2, 3, 4)
b <- c(5, 6)

# This now raises a clear error instead of silently recycling:
distance(a, b)
Error in distance(a, b): x and y must be the same length
# On vectors of equal length it works as intended:
distance(c(1, 2, 3, 4), c(5, 6, 7, 8))
[1] 8

Because doubles are stored to finite precision, 0.1 + 0.2 is not exactly 0.3, so == returns FALSE. Comparing with all.equal(), which allows a tiny tolerance, gives the intended result. We wrap it in isTRUE() because all.equal() returns a message rather than FALSE when the values differ, which would not behave correctly inside if.

a <- 0.1 + 0.2
b <- 0.3

if (isTRUE(all.equal(a, b))) {
    print("Values are equal.")
} else {
    print("Values are not equal.")
}
[1] "Values are equal."
